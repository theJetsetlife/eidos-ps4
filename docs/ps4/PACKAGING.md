# PS4 packaging

Two routes take the SDK 12.508.041 ELF to a PKG.

| Route | Script | CMake target | Runs on |
|---|---|---|---|
| Official Publishing Tools 4.12 | `tools/ps4/make_pkg_official.sh` | `eidos_ps4_minimal_pkg` | Development/test kits |
| Fake-signed | `tools/ps4/make_fpkg.sh` | `eidos_ps4_minimal_fpkg` | Consoles that install fake PKGs |

```sh
export SCE_ORBIS_SDK_DIR="$(cat /tmp/eidos-orbis-sdk-path)"
export PATH="/tmp/eidos-build-tools/bin:$PATH"
cmake --build /tmp/eidos-orbis-diagnostics --target eidos_ps4_minimal_pkg
```

## Optimized game test package

Use the game release configure preset before the packaging build preset:

```sh
cmake --preset ps4-game-release
cmake --build --preset ps4-game-fpkg
```

The game release preset selects `-O2 -DNDEBUG` for both C and C++. A target
named `eidos_ps4_release_fpkg` uses its existing build directory's flags; its
name alone does not turn an unoptimized configuration into a release build.
Keep debug presets available for debugging. Validate optimized host gameplay
before deploying changes: optimization can expose native ABI defects that an
unoptimized run missed. Package validation establishes file integrity and
contents; console performance and gameplay remain separate acceptance gates.

## Official route

`orbis_pub_cmd.exe` 4.12 runs through Proton.

1. The unmodified SDK ELF becomes `eboot.bin`, as the SDK documents.
2. `libc.prx` and `libSceFios2.prx` are copied from `target/sce_module`.
   `img_verify` requires Fios2 whenever libc is present.
3. `param.sfx` → `sfo_create` → `param.sfo`. ATTRIBUTE 2 makes Cross the
   confirm button in common dialogs.
4. `gp4_proj_create` (pkg_ps4_app, digital50), `gp4_file_add`, then
   `img_create --oformat pkg`.
5. `img_verify` output is in `verify.txt`, the package contents in
   `file_list.txt`, and the hashes in `manifest.txt`.

Publishing Tools setup: extract the whole
`PublishingTools-4_12_0_0-10081bb48.msi`, not just `orbis_pub_cmd.exe`, and
put `sc.exe` and `di.exe` under `ext/`. Without `ext\sc.exe` every command
fails with "The version of sc.exe is invalid or missing". The script
defaults to `$SCE_ORBIS_SDK_DIR/../publishing-tools-4.12`, or you can set
`SCE_PUBTOOLS_DIR`.

Current diagnostic result: `img_verify` reports 0 errors and 4 warnings.

- No `nptitle.dat`. The diagnostic uses no NP features.
- No NEO mode support. Base PS4 is the baseline; a Pro mode is not implemented.
- The TRC R4211 PS5 test reminder.
- No trophy pack (TRC R4124).

Fixing those is release work, not part of the diagnostic.

## Fake-signed route

1. Optional: `patch_sdk_version.py` writes a copy of the ELF with a different
   process-param SDK version.
2. `third_party/make_fself_py3.py`, a Python 3 copy of OpenOrbis
   `make_fself.py` regenerated by `port_make_fself.sh`, writes a
   fake-signed `eboot.bin`.
3. `check_fself.py` verifies it against the ELF.
4. `--module` fake-signs SDK PRX files. PkgTool.Core then writes the SFO,
   gp4 and PKG, and `pkg_validate` checks the result.

Kept copies are in `build/pkg/diagnostic-official/` (official) and
`build/pkg/diagnostic/` (fake-signed, with the source ELF).

On hardware, the diagnostic shows 1080p color bars for 600 frames (about
10 s), plays a one-second tone, and exits early when Cross is pressed.
Messages go to `printf` (the kernel/target log).

## Prerequisites and limits

- An official PKG holds an unsigned development ELF. It installs and runs
  on a development or test kit in the matching mode, not on retail
  firmware. A signed retail build needs Sony's submission and signing
  through an authorized publishing account.
- A fake PKG needs a console with fake-PKG support. On firmware older than
  SDK 12.508, the loader may refuse the version, or imports the firmware
  lacks fail to resolve. Firmware 13.52 is newer than the SDK.
- Install, launch and runtime behavior are unverified on both routes.
- ROMs, extracted game data, SDK modules and the game executable stay out
  of Git. SDK files go only into the local `stage/` and the PKG.
